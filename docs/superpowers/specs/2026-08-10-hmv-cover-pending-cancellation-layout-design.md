# HMV 确认邮件封面与待导入取消布局修复设计

## 背景与已确认根因

生产环境存在两个回归问题：

1. 待导入订单详情页虽然渲染了取消表单，但表单是统一网格中的独立第二行。以 CDJapan 订单 `10115229066` 为例，取消按钮位于页面约 1933px 处，而首屏高度为 969px；视觉上无法像已导入订单一样在右侧操作栏找到它。
2. HMV 新订单确认邮件包含官方专辑封面，但使用 `https://www.hmv.co.jp/en/product/detail/{id}` 商品链接和 `https://img.hmv.co.jp/image/jacket/.../{id}.jpg` 封面。现有白名单只接受旧的 `/product/detail/{id}` 与 `/img.asp?sku={id}`，且订单确认分支没有执行 HTML 商品元数据合并，因此 7 个商品均没有封面和商品链接。

真实邮件只用于内存诊断，不写入仓库。诊断结果表明，新模板的 7 个文本商品与 7 组 HTML 商品元数据能够按规范化标题一一唯一匹配。

## 选定方案

采用方案 A：重构待导入订单的表单归属，使右侧栏同时容纳订单基础信息和整单取消卡片；扩展 HMV 官方 URL 白名单，并让订单确认邮件复用现有 HTML 元数据合并逻辑。

不采用纯 CSS 强制定位，因为它会依赖当前商品数量和响应式网格高度；不把取消卡片移到页面顶部，因为这会与已导入订单详情的交互位置不一致。

## 详情页布局

- 待导入订单继续使用一个导入表单提交全部商品与订单金额。
- 左侧商品输入保留在商品列表中，通过标准 HTML `form` 属性归属到右侧导入表单，避免嵌套表单。
- 右侧 `aside` 依次放置订单基础信息导入表单和 `OrderCancellationForm`，结构与已导入订单的右侧操作栏一致。
- 手动取消后，所有导入字段保持禁用，导入按钮隐藏，取消卡片切换为恢复操作。
- 恢复后重新启用导入字段与导入按钮。
- 不在订单列表页新增取消按钮；取消与恢复仍只在详情页执行。

## HMV URL 与解析规则

- 保留对旧版 `https://img.hmv.co.jp/img.asp?sku={数字}` 封面的支持。
- 新增对 `https://img.hmv.co.jp/image/jacket/{纯数字路径}/{数字}.jpg` 的支持；仅允许 HTTPS、精确官方主机、无用户名和密码、无额外路径或非 JPG 扩展。
- 保留旧版 `/product/detail/{数字}` 商品链接，并新增精确的 `/en/product/detail/{数字}` 路径；查询参数与片段不会进入规范化结果。
- 相似恶意域名、HTTP、凭据 URL、非数字商品 ID 和额外路径继续拒绝。
- HMV 订单确认、发货和取消邮件统一尝试从 HTML 合并商品元数据。
- 优先使用商品链接内的直属封面；同一商品的文本链接不会覆盖此前已找到的封面。
- 只有标题匹配唯一时才合并封面和商品链接；歧义或无匹配时保留占位图。

## 数据流与上线处理

1. QQ IMAP 读取 HMV 原始邮件。
2. 文本部分解析订单号、金额和商品；HTML 部分解析可信商品链接与封面。
3. 按规范化标题一一匹配，将封面和商品链接写入订单确认载荷。
4. 重新执行一年全量同步，使既有 HMV 待导入事件更新为新载荷。
5. 待导入详情页直接展示可信远程封面；正式导入时沿用现有封面存储流程。

同步或 HTML 元数据匹配失败不会阻止订单文本解析；对应商品继续使用占位图。邮件金额、商品数量和订单状态规则不变。

## 测试与验收

- URL 单元测试覆盖新旧 HMV 封面、英文商品链接以及恶意相似 URL。
- HMV 解析测试使用脱敏的新模板结构，先证明确认邮件目前无法获得封面，再验证全部匹配商品得到可信封面与商品链接。
- 详情页组件测试要求“确认取消订单”按钮位于 `complementary` 右侧栏内，而不只检查按钮存在。
- 详情页测试继续覆盖手动取消后隐藏导入、显示恢复操作。
- 运行 `pnpm test`、`pnpm lint`、`pnpm typecheck`、`pnpm build`。
- 上线后重新执行一年全量同步，并验证：
  - HMV 目标确认邮件的 7 个商品均有可信封面和商品链接；
  - `10115229066` 的取消卡片紧邻右侧订单基础信息，不再落到全部商品之后；
  - 取消和恢复各执行一次后，订单最终恢复为原始待导入状态。

## 范围外事项

- 不抓取 HMV 官网商品页。
- 不接受邮件样本之外的 HMV 图片主机或任意图片路径。
- 不改变其他商家的封面规则、订单金额或状态逻辑。
