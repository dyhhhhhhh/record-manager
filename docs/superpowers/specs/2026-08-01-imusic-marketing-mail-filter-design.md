# iMusic 营销邮件服务器端过滤设计

## 目标

首次回溯和后续增量同步都不返回 iMusic 营销邮件的邮件头，只搜索三类业务邮件：下单确认、发货通知和取消通知。

## 设计

QQ IMAP 搜索继续使用 `FROM imusic.dk`，并保留首次同步的 `SINCE` 或增量同步的 UID 范围。在同一次服务器端搜索中增加三个 `SUBJECT` 条件，以 `OR` 组合：

- `Order Acknowledgment`
- `Your order has been dispatched`
- `Order cancelled`

IMAP 的 `SUBJECT` 是包含匹配，因此无需把订单号放进搜索条件。服务器返回 UID 后，现有本地分类器仍以完整正则校验发件域和标题格式，防止相似标题或服务端搜索差异进入解析流程。

## 边界与错误处理

- 不搜索正文，不改变邮件已读状态。
- 不改变同步游标、去重、确认和订单业务流程。
- QQ IMAP 搜索失败时沿用现有行为：整次同步失败且不推进游标。
- 不额外支持营销邮件的人工导入。

## 测试

- 纯函数测试验证首次搜索同时包含发件域、日期和三个标题。
- 纯函数测试验证增量搜索同时包含发件域、UID 范围和三个标题。
- 继续运行现有同步、解析、类型检查和生产构建测试。
