# 手机端订单操作区设计

## 目标

缩短手机端订单卡片的纵向高度，让“详情”和“导入”操作在浏览订单号时立即可见。桌面端现有操作列保持不变。

## 布局

- 小于 `768px` 时，订单卡片首行使用两列布局。
- 左列展示订单 ID、外链图标及“下单、发货、取消”邮件标签；标签空间不足时在订单 ID 下方自然换行。
- 右列展示操作按钮：始终显示“详情”，满足导入条件时在其左侧显示“导入”。
- 日期、状态和金额信息区位于首行下方，并横跨订单卡片全宽。
- 大于等于 `768px` 时，不改变现有日期、状态、金额和操作分列布局。

## 交互与无障碍

- “详情”和“导入”继续使用明确的文字标签，不改为纯图标或折叠菜单。
- 按钮高度保持至少 `44px`，导入中的禁用与加载状态维持现有行为。
- 调整只涉及 CSS Grid 位置，不复制表单或操作元素，避免重复可聚焦控件。
- 不改变订单详情链接、导入 Server Action、筛选、分页或订单状态逻辑。

## 响应式边界

- 在约 `390px` 宽度下，只有“详情”时靠右显示；同时存在“导入”和“详情”时两个按钮并排。
- 更窄屏幕中优先让邮件标签换行，订单 ID 与操作按钮保持首行可用。
- 卡片不得产生横向滚动；桌面布局和对齐不得回退。

## 验证

- 增加订单行布局测试，确认手机端首行网格定位类和桌面端重置类存在。
- 运行 Vitest、类型检查、lint 和生产构建。
- 在 `390 × 844` 视口检查仅详情、可导入两种订单行，并确认订单页无横向溢出。
